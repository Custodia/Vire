# 0002. Backend stack

## Context

Vire serves a dashboard, a JSON API and an MCP endpoint to a handful of users,
and runs background work beside them: syncing from Garmin, decoding `.fit` files,
importing nutrition exports. Its schema leans on PostgreSQL: enum types, date
ranges, exclusion constraints and triggers.

## Decision

Vire is one Elixir release against one PostgreSQL database.

- **Phoenix** serves the built dashboard, the JSON API and the MCP endpoint.
- **Ecto with Postgrex** holds the data. Whatever Ecto has no syntax for is
  written as SQL inside the migrations.
- **Oban** runs background jobs in the same VM, with its queue, retries and cron
  in Postgres.
- Primary keys are UUIDs generated by the database. Timestamps are `timestamptz`.

## Consequences

There is one artifact to deploy and one database to back up. A job and the rows it
writes share a transaction, and a job enqueued inside a transaction exists only if
that transaction commits.

Web requests and jobs share the VM's schedulers and memory, so a heavy job slows
requests down.
